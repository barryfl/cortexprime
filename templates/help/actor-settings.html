Actor Configuration — GM Guide

Actor Settings defines the reusable Actor Types used by the Cortex Prime system. An Actor Type controls sheet structure, enabled sections, Trait Sets, preset Traits, and many presentation and behavior options.

Changes to an Actor Type can be synchronized to existing Actors without resetting their normal actor-local play state.

Actor Types

Create separate Actor Types when different kinds of Actors need different sheet structures. For example, a player character, NPC, vehicle, or Doom Pool could each use its own Actor Type.

Actor Types can be created, edited, reordered, and deleted from Actor Settings. Deleting an Actor Type removes the configuration definition; it does not automatically delete existing Actors that used it.

Tabs

Actor Types can define their own ordered sheet tabs. Trait Sets and other sheet sections can be assigned to those tabs.

  • Tabs use stable internal IDs, so renaming or reordering a tab does not break assignments.
  • The final remaining tab cannot be deleted.
  • If a tab is deleted, affected sections are reassigned using the system's normal fallback behavior.
  • The Notes tab remains a special optional tab controlled by the Actor Type's Notes setting.

Sheet Sections and Layout

The major sheet sections are peers that can be placed into configured tabs. These include Profile/Identity, Plot Points, Trait Sets, Assets, and Complications.

Sections can be configured with:

  • Enabled: whether the section is shown.
  • Tab: which configured tab contains the section.
  • Order: where the section appears relative to other sections.
  • Width: the section's layout width, such as full, half, or third where supported.

Feature toggles such as Plot Points, Assets, or Complications remain authoritative: disabling the feature prevents stale layout configuration from forcing the section to appear.

General Actor Features

  • Show Profile Image: displays the actor portrait where the Profile section is enabled.
  • Has Notes Page: enables the Notes tab.
  • Has Plot Points: enables dedicated Plot Point tracking.
  • Has Assets: enables the specialized Assets section and Add Asset control.
  • Has Complications: enables the specialized Complications section and Add Complication control.
  • Has Hidable Traits: enables actor-local hiding/suppression of inherited Traits.

Trait Sets

Trait Sets are the major Trait categories used by your Cortex build: Distinctions, Attributes, Skills, Values, Relationships, Roles, Powers, Stress, or any other category you need.

Trait Sets can be created, renamed, reordered, moved between tabs, assigned section width/order, and deleted.

Trait Set Capabilities

Depending on configuration, Traits in a set can support:

  • descriptions;
  • display labels;
  • descriptors;
  • SFX;
  • Sub-Traits;
  • dice;
  • consumable dice;
  • custom Traits created on individual Actors.

Settings that depend on another capability may be disabled until their parent option is enabled. For example, consumable dice require dice support.

Custom Trait Permission

The GM can allow players to create custom Traits in selected Trait Sets. GMs can create custom Traits even when player creation is disabled.

Preset Traits and Typed Values

Preset Traits are defined on the Actor Type and supplied to Actors using that template. Ordinary Traits support these value types:

  • Die: Cortex die value with permanent and temporary-step controls.
  • Number: editable numeric value.
  • Text: editable text value.
  • Resource: numeric counter with minimum, maximum, default, step size, and optional image presentation.

Sub-Traits can remain diceless or use dice when the Trait Set enables them. This can represent specialties or other nested Trait structures without requiring a separate subsystem.

Die Trait Images

Die Traits can optionally use an image for presentation. The available modes are designed to leave existing sheets unchanged unless the GM opts in.

  • None: no image; the normal Add to Dice Pool control is shown.
  • Icon: show the image before the normal Add to Dice Pool control and Trait label.
  • Replace Add to Pool: use the image itself as the Add to Dice Pool control.

If a replacement image is missing or invalid, the normal Add to Dice Pool control is used as a safe fallback.

Resource Trait Configuration

Resource Traits track a current value separately from their Actor Type configuration. Configure minimum, maximum, starting/default value, and step size as appropriate.

Resource image presentation supports the established Resource modes:

  • None: normal counter controls only.
  • Icon: show a noninteractive image beside the Resource.
  • Consume: use the image in place of the decrement/consume control.

Actor Type synchronization preserves the Actor's current Resource amount while updating configuration.

Synchronizing Existing Actors

Actor Type synchronization is intentionally non-destructive. It pushes current template structure and configuration while preserving actor-local play state wherever possible.

Synchronization can update:

  • tabs and section layout;
  • Trait Set definitions and configuration;
  • preset Trait definitions and labels;
  • value types and presentation metadata;
  • descriptors, SFX, Sub-Traits, and other inherited configuration.

Synchronization preserves actor-local mutable state such as current Trait values, Resource amounts, custom Traits, temporary die steps, hidden inherited Traits, Assets, Complications, Plot Points, and similar play-state data.

Deleting and Hiding Content

Template/configuration deletion and actor-local deletion are different operations.

  • Deleting Actor Type configuration changes the template.
  • Deleting actor-local content such as a custom Trait, Asset, Complication, or Note removes that local entry.
  • Inherited Traits on one Actor are hidden/suppressed rather than destructively deleted, so synchronization does not recreate an unwanted Trait immediately.

Hidden inherited Traits can be restored later and retain their actor-local state.

Theme Settings

Theme Settings controls the module's supported visual theme options, including configured fonts, backgrounds, borders, dice presentation, and other available theme properties.

Theme changes are separate from Actor Type mechanics. Use Theme Settings for appearance and Actor Settings for sheet structure and Trait behavior.

Import / Export Settings

Import / Export Settings can save or load the system's supported configuration data. Existing compatibility behavior is preserved for older Actor Type data where possible.

Import does not require opening every Actor to force a migration; the system uses runtime normalization for supported legacy structures.

Saved Dice Pool Cleanup

Export to Macro stores reusable Dice Pool recipes. Because deleting a Foundry Macro does not necessarily delete its saved recipe, the system includes a GM-only cleanup utility.

Open Saved Dice Pool Cleanup from the Cortex Prime system settings. It scans saved recipes across users and compares them with the world's Cortex Prime Dice Pool Macros.

Referenced recipes are protected. Unreferenced recipes are shown as unused and may be selected for deletion. Macro identity is tracked by stable Cortex metadata rather than by visible Macro name or folder, so moving or renaming a Macro does not falsely orphan its recipe.

GM Workflow Recommendation

  1. Create or select an Actor Type.
  2. Configure its tabs and enabled sheet sections.
  3. Create Trait Sets and assign each one to a tab/layout position.
  4. Enable the Trait Set capabilities you need.
  5. Add preset Traits and select their value types.
  6. Configure optional images, Resources, Sub-Traits, SFX, descriptors, or custom-Trait permissions.
  7. Create a test Actor and verify the sheet before synchronizing existing Actors.
  8. Use Help and tooltips as a player-facing reference rather than trying to encode your game's Cortex rules into the module itself.
