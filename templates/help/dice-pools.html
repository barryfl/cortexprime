Dice Pools and Rolling

The Dice Pool is a temporary staging area for a roll. Add the Traits and other dice that apply, make any final adjustments, then roll.

Building a Dice Pool

Use Add to Dice Pool on a rollable Trait. Deliberately adding dice opens the Dice Pool automatically.

Trait-backed dice remain linked to their source. If a Trait has a temporary step adjustment, its current effective die is what enters the pool.

You may also add supported literal/custom dice where appropriate. A pool can contain dice from more than one Actor.

Removing Dice

  • Remove Source: removes one source/group from the current pool.
  • Clear Pool: empties the entire current pool.

The Pool Is Temporary

The Dice Pool is intentionally ephemeral. A successful roll clears and closes it. Closing the Dice Pool without rolling also clears it.

If you deliberately add a Trait or send dice to the pool later, a fresh pool is created and opened.

Rolling

Use the Dice Pool's roll controls to roll the assembled dice. The result picker lets you choose the dice used for the result according to the rules of your game.

Total

Select the dice that form the Total according to your Cortex Prime rules.

Effect Die

Select the appropriate unused die as the Effect Die when your game uses one.

Hitches

Dice that roll 1 are identified as hitches by the roll interface.

Re-Roll

Chat-result controls can re-roll an existing result when permitted by your game.

To Pool

Supported chat results or selected dice can be sent back to the Dice Pool. Sending dice to the pool opens it automatically.

Export to Macro

If you build the same pool frequently, choose Export to Macro. Give the Macro a name and the system creates a reusable Foundry Macro.

When possible, the saved recipe stores references to the actual Actor Traits rather than freezing their current die sizes. Clicking the Macro later resolves those Traits again, rebuilds the pool using their current effective values, and opens the Dice Pool for any situational additions. The Macro does not roll automatically.

Literal/custom dice that do not have a Trait source are saved as literal dice.

Exported Macros are organized into a folder named: Cortex Prime Dice Pools - <User Name>. The friendly folder name is for organization; the system tracks the owning user internally so folder reuse remains reliable.

If a referenced Trait is later hidden, deleted, or otherwise unavailable, the Macro skips unavailable sources and warns you rather than silently using a stale die. Restoring a hidden Trait allows the Macro to resolve it again.

GM: Saved Dice Pool Cleanup

Exported Macro recipes are stored separately from the transient Dice Pool. If a Macro is deleted, its saved recipe may remain behind.

GMs can use Saved Dice Pool Cleanup from the Cortex Prime system settings. The cleanup tool scans users' saved recipes and world Macros, identifies recipes that are no longer referenced, and lets the GM delete only those unused recipes.

Macro names and folders are not used as the authoritative match, so renaming or moving an exported Macro does not make its recipe appear unused.
